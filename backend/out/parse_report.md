## 5. 文档自身的问题（解析发现的，不是解析错误）

1. **实践学分两处数字不一致**：“毕业学分要求”写 38.25，“实践教育环节”标题写 38.75。逐项相加为 38.75，可判定 38.25 为笔误。
2. **“智能装备设计制造实践”（课程表，8 学分）与“智能装备设计制造综合实践”（实践表，8 学分）疑似同一门课**，两处命名不一致，需教务确认。
3. **“工程模块”“智能模块组”不是普通类别**：注释写明“为必修，可选表中若干课程，也可选分流专业的对应课程，学分按规定置换”，因此它们应当建成 `module_group`（组内全修 + 允许置换），不能当普通必修逐门硬编码。
4. **专业选修无课程明细**：正文只写“选修范围包括工学院、信电学院……”，未列课程与学分，系统只能记录“需修 9/6 学分”这一约束，无法生成候选清单 —— 这正是需要“用户确认/学校课程库”补充的地方。

## 7. 与“任意培养方案”的关系

这份 `curriculum.json` 里没有任何一处写死了“智能装备试验班”的课程。换一份方案，变的是数据，不是代码：

- 层级结构固定为 `模块 → 课程组 → 课程`，组规则只有 `all_of / credits / pick_n / pick_n_of` 四种；
- 学分可以声明为单值，也可以是 `{"植物模块": 75.5, "动物模块": 78.5}` 这种分方向字典；
- 课程行靠“学分锚点 + 邻居字段形态”识别，不依赖列序；换排版只需改抽取适配器；
- 所有对不上的数字都进 `issues`，不静默修正 —— 这是“通用”能站住的前提。

python backend/curriculum_parser.py "<培养方案.doc>" backend/out/curriculum.json
